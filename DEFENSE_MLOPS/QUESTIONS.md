# Возможные вопросы преподавателя

## Данные и эксперименты

1. **Зачем DVC, если есть Git?** Git хорошо хранит код и небольшие тексты. DVC
   хранит граф вычислений и checksums больших/генерируемых данных, не заставляя
   помещать CSV в обычную историю Git.
2. **Что именно фиксирует `dvc.lock`?** Команды stage, зависимости, параметры и
   hashes выходов. По ним видно, какие изменения требуют пересчёта.
3. **Почему две версии данных, если исходный CSV один?** Это две воспроизводимые
   версии preprocessing: minimal и standard, каждая с manifest и content ID.
4. **Как исключена утечка между splits?** Сначала удаляются точные дубликаты,
   затем выполняется единый стратифицированный split; пересечения текстов
   проверяются кодом.
5. **Зачем MLflow?** Он связывает параметры, метрики, data version, code SHA и
   artifacts каждого run, поэтому сравнение экспериментов проверяемо.
6. **Почему не выбирали модель по test?** Это дало бы оптимистичную оценку.
   Модель и threshold выбраны по validation; test применён один раз в конце.
7. **Что такое F1?** Гармоническое среднее precision и recall. Метрика полезна,
   когда положительный класс редкий и важны оба вида ошибок.
8. **Почему PR-AUC важнее одной accuracy?** Toxic-класс несбалансирован.
   PR-AUC показывает trade-off precision/recall именно для положительного класса.
9. **PR-AUC и ROC-AUC — разница?** ROC-AUC сравнивает TPR и FPR; при сильном
   дисбалансе может выглядеть слишком оптимистично. PR-AUC чувствительнее к
   качеству положительного класса.
10. **Как работает TF-IDF?** Частота терма в документе усиливается, а слова,
    часто встречающиеся во всём корпусе, ослабляются. Здесь используются
    униграммы и биграммы.
11. **Почему Logistic Regression?** Она быстро обучается на разреженных
    TF-IDF-векторах, даёт вероятности, интерпретируема и показала лучший
    validation F1 среди проверенных baseline.
12. **Почему threshold не 0,5?** Он подобран на validation для максимального F1;
    итоговое значение `0.664350614731206` затем зафиксировано в metadata.

## Serving и контейнеры

13. **Как FastAPI получает модель?** В lifespan startup inference-класс
    проверяет metadata и SHA-256 joblib, затем один раз загружает sklearn Pipeline.
14. **Почему preprocessing не написан отдельно в API?** Он входит в sklearn
    Pipeline, поэтому обучение и serving используют одну реализацию.
15. **Что возвращает `/health`?** Готовность, model/data version, threshold и
    checksum — этого достаточно для диагностики развернутой версии.
16. **Почему невалидный текст возвращает 422?** Pydantic проверяет схему,
    непустую строку и длину до вызова модели; это ожидаемая клиентская ошибка.
17. **Что такое Docker image и container?** Image — неизменяемый шаблон с кодом
    и зависимостями; container — запущенный экземпляр этого image.
18. **Какие меры безопасности есть в Docker?** Non-root UID 10001, read-only
    filesystem, `no-new-privileges`, dropped Linux capabilities, hash-locked
    packages и pinned base-image digest.
19. **Как Streamlit общается с API?** Делает HTTP POST на
    `${API_BASE_URL}/predict`; в Compose это `http://api:8000` во внутренней сети.
20. **Почему UI не загружает модель сам?** Иначе появились бы две независимые
    версии serving и риск расхождения preprocessing/threshold.

## Git и CI/CD

21. **Что такое CI/CD?** CI автоматически проверяет каждое изменение; CD
    доставляет проверенные artifacts. Здесь CI полностью реализован, а на tag
    выполняется controlled delivery images в GHCR.
22. **GitHub Actions отличается от локальных тестов?** Workflow запускается в
    чистой Ubuntu-среде по commit, поэтому обнаруживает скрытые зависимости от Mac.
23. **Что проверяет workflow?** Ruff, pytest, coverage gate 80%, reports,
    сборку API+UI, health/predict/UI smoke, UI→API и публикацию на version tag.
24. **Зачем Git tag?** `v1.2.0` неизменяемо связывает исходники, lock-файлы,
    Dockerfiles, config и модель одного release.
25. **Почему version проекта и модели разные?** Модель не переобучалась после
    исправлений инфраструктуры. Release `v1.2.0` содержит прежний проверенный
    artifact `toxicity-tfidf-logreg-v1.0.0`.
26. **Как воспроизвести обучение?** Получить Jigsaw по README, установить
    `requirements-train.lock`, выполнить `dvc repro` или соответствующие stages.
27. **Как проверить, что API использует MLflow artifact?** SHA-256 joblib API и
    файла в selected run одинаков: `3e98...b3d`; это проверено побайтово.
28. **Где секреты?** В Git их нет. Локальные значения задаются через env;
    CI использует выдаваемый GitHub `GITHUB_TOKEN`, который не коммитится.
29. **Что мониторить в production?** Latency, errors, class/probability drift,
    изменение языка/тематики и качество на размеченной свежей выборке.
30. **Главное ограничение?** Jigsaw и модель ориентированы на английский текст;
    ошибочные флаги возможны, поэтому система не должна единолично наказывать
    пользователя без процесса апелляции.
